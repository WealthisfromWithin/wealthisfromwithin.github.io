# Wave 7 Security Review — Implementer's posture statement

**Date:** 2026-08-05 · **Wave:** 7 (Production Hardening)
**Status:** implementer's own assessment. GPT-5.5 review is the gate, not this.

## The one-sentence model

**Nothing here is protected, because nothing here is sensitive.** The surface is
public, holds no credential, has no session, and stores only what one operator
typed into their own browser. That model is coherent and it is currently true —
and it stops being true the day private data arrives, which is why authentication
is a *prerequisite* for private mode rather than a feature shipped alongside it.

## Wave 7 changes

### Control 4 (CSP on the built index) — shipped

Deferred since the Wave 1 fix pack. Now delivered as a `<meta http-equiv>`
injected at build time by the `sovereign-csp` plugin, generated by
`src/lib/csp.ts` and covered by 10 tests:

```
default-src 'self'; base-uri 'self'; script-src 'self';
style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self';
connect-src 'self'; manifest-src 'self'; worker-src 'self';
object-src 'none'; frame-src 'none'; form-action 'none'
```

What this actually buys: an exfiltration path introduced by a compromised
dependency has nowhere to send to, because `connect-src` is `'self'` in the
public build. That is the threat this policy is really aimed at — not XSS, which
was already low.

Two honest caveats:

- **`style-src` keeps `'unsafe-inline'`.** `index.html` carries an inline
  `<style>` painting the background before the stylesheet arrives. Hashing it
  would turn a future edit into a silent white-flash regression. Inline *style*
  is a materially smaller risk than inline script, which is forbidden outright.
- **`frame-ancestors` is not delivered at all.** Browsers ignore it in a meta
  tag, so it is emitted only by the header form of the builder — and Pages
  cannot set headers. **Clickjacking protection is absent, not partial.**
  `src/lib/csp.test.ts` asserts the meta form omits it, so nobody can read the
  built policy and believe otherwise.

### The connected-probe invariant — a trust control, not a feature

Wave 6's review (L1) flagged that `connected` was *defined* as "verified by a
health probe" and *enforced* by nothing. It was a convention, and conventions
fail silently.

It is now enforced three ways:

- **Write** — `recordIntegrationProbe` is the only writer that can set
  `connected`, and it refuses a result whose timestamp is missing or unparseable.
- **Read** — `effectiveIntegrationState` downgrades any unevidenced `connected`
  claim to `awaiting_credentials` at every consumer: registry, MCP panel, Health
  Monitor counts and substrate pills, the content publishing panel, state counts,
  blocked capabilities, search index.
- **Gate** — `automationReadiness` asks `isUsable`, so an unevidenced claim
  cannot make a rule runnable and `runAutomation` refuses it with the reason
  recorded.

Both halves matter. The writer governs what is written from now on; the read-time
downgrade governs rows already in an operator's browser and rows a hand-edited
IndexedDB could contain — and IndexedDB **is** editable by hand from devtools,
which is exactly why a write-side check alone would have been insufficient.

The gate is the half Wave 7 shipped incomplete. The downgrade existed, but four
modules still read `integration.state` directly, and one of them decided whether
an automation could write. Since a bypass reads perfectly naturally, the
invariant is now also enforced against the source:
`src/integrations/invariant.test.ts` fails the build if any module outside
`src/domain/integrations.ts` reads the stored field.

Enforcing it as a schema refinement was considered and rejected: a stored row
failing validation would lock an operator out of their own store, hiding the
problem behind an error boundary rather than showing it.

### Both outbound adapters refuse before sending

The two `fetch` call sites in the codebase each validate their URL before
building a request:

| Adapter | Refuses |
|---------|---------|
| Command API (`/sync`) | Unparsable URLs; non-HTTPS on a public host; **userinfo** (`https://user:token@host`); **query strings or fragments** (`?api_key=…`) |
| Local model (`/ai`) | Any non-loopback host — LAN and private addresses included, because they are other machines |

Both refuse *without sending anything*, not even a probe. The probe itself sends
`credentials: 'omit'` and no headers, and only the **host** is ever printed in
the UI — never the full URL, precisely because a misconfigured value may carry
userinfo.

Both rules live in `src/lib/endpoints.ts`, and the CSP builder asks the same two
functions. A refused value therefore produces **no `connect-src` entry**: the
policy cannot grant a destination the adapter would not call. Wave 7 originally
had the CSP re-derive origins with a looser check of its own, which meant a
misconfigured build could widen `connect-src` for an origin nothing in the app
would ever request — an exfiltration destination granted for nothing.

## Residual risks accepted

| Risk | Severity | Why accepted |
|------|---------:|--------------|
| No clickjacking protection | Low | No session, no credential, no destructive one-click action. Framing this surface gains an attacker nothing. **Reassess before auth ships** |
| IndexedDB unencrypted at rest | Low→High | Low while the store holds demo data and one person's notes. High the moment it holds anything real. Protected only by the OS user account |
| Public surface, no access control | Low | Nothing sensitive is served. Inverts entirely with private data |
| Unbounded local log | Low | A storage-growth issue, not a disclosure one |
| `style-src 'unsafe-inline'` | Low | Inline style cannot execute. The alternative is a fragile hash |
| Dependencies inlined into a public bundle | Low | 10 runtime dependencies, no provider SDKs, and `connect-src 'self'` denies a compromised one anywhere to send |

## What must happen before private data

Non-negotiable, in order:

1. **Command API with session auth.** `HttpOnly`, `Secure`, `SameSite=Strict`
   cookies — never a bearer token handed to JavaScript in a public bundle.
2. **CSP as a response header**, including `frame-ancestors 'none'` and HSTS.
   `buildContentSecurityPolicy({ delivery: 'header' })` already emits it; it
   needs a host that can send it. See [`OPERATIONS.md`](../OPERATIONS.md) §6.
3. **Server-side credential vault.** Probes run server-side and return state and
   timestamp only, never the secret.
4. **Rate limits** on auth, AI, and any webhook.
5. **Server-side audit log.** The local one covers one browser.
6. **Encryption at rest**, on the server. IndexedDB will not be the store of
   record for anything private.

Until all six exist, staying demo-local is not a limitation to apologise for. It
is the control.
